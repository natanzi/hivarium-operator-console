| Boundary | Description |

## STRIDE Threat Register (ASVS Level 1)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Tampering | recordUsage atomic write | high | mitigate | Append the UsageRecord and linked usage_debit in one DataStore write; validate customer/prepaid/agent references and the no-negative guard through pure rules before any write (ASVS V5 input validation). |
| T-02-08 | Tampering | sourceReference idempotency | high | mitigate | Normalize the locked fingerprint fields and compare exact sourceReference across the store; exact replay performs no write, conflicting reuse throws a descriptive error naming the reference (D-09, USGE-02). |
| T-02-09 | Tampering | reverseTransaction | high | mitigate | Reject reversal-of-reversal and any target already referenced by a reversal; negate the full target amount exactly once; run the no-negative guard before one write (D-05). |
| T-02-10 | Tampering | applyManualAdjustment | high | mitigate | Require a non-zero signed whole-token amount and a reason/reference; reject any adjustment that would make the derived balance negative before one write (D-06, LEDG-04). |
| T-02-11 | Repudiation | usage/adjustment/reversal mutations | medium | mitigate | Every balance-changing action ends in a named-customer confirmation previewing the resulting balance; each mutation appends an immutable transaction with deterministic ID, occurredAt, reason, and reference in the same write (D-07, SAFE-02). |
| T-02-12 | Information disclosure | localStorage | medium | accept | Prototype boundary retains deterministic fictional data only; no real financial data or network transmission is introduced (ASVS V8 client-side data protection). |
| T-02-13 | Denial of service | malformed persisted arrays / huge values | low | mitigate | Bounded shape normalization, deterministic seed fallback, and whole-token range validation prevent render crashes and absurd balances. |
</threat_model>
